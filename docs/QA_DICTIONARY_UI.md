검증일: 2026-09-15

검증 환경:

- 프런트: `http://localhost:5173`, Docker `ubidic-frontend-1`
- 백엔드: `http://localhost:8080`
- DB: Docker MySQL `ubidic-mysql-1`
- 로그인: 기존 Google 로그인 계정 1개

## 발견한 상태 이슈

- QA 시작 시 `review_request.id=1`이 `REVISED` 상태여서 `개정안/current` 화면이 “진행 중인 사전집 개정안이 없습니다.”로 표시됐다. 개발용 QA를 위해 상태를 `CHANGES_REQUESTED`로 복원한 뒤 리뷰 화면을 검증했다.
- 추출 콜백 500의 원인은 `CandidateTerm.createExisting()`가 MySQL NOT NULL 컬럼에 `occurrenceCount=null`을 저장하던 오류였다. 기존 용어의 추출 출현 횟수를 0으로 저장하도록 수정했고, 관련 repository/service 테스트를 통과시켰다.
- 개발 프로파일의 `ddl-auto=create-drop`로 재시작 시 QA DB가 삭제되던 문제도 `validate`로 변경했다. 이번 검증은 Flyway 스키마를 유지하고 루트 MySQL에 명시적으로 연결해 수행했다.
- diff QA를 위해 사전 r2를 추가하고 r1을 보관 처리했다. r2에는 `결제` 정의 변경과 신규 `정산`을 넣었으며, 화면 diff는 신규 1건으로 집계됐다. 현재 diff API는 정의 변경을 변경 건수로 표시하지 않는 정책(D-41)도 화면에서 확인됐다.
- 현재 워크스페이스의 `required_dictionary_reviewer_count`가 0이므로 리뷰 화면에 `필요 정족수 0`이 표시되고, 변경요청 리뷰가 있어도 반영 버튼이 활성화될 수 있다. 이는 현재 백엔드의 0 정족수 정책과 일치한다.
- QA 데이터는 개발 MySQL에 직접 삽입된 목업 데이터이며 운영 데이터로 사용하면 안 된다.

## 결론

리뷰 화면 수정 범위인 최신 리뷰 집계, 이전 리뷰 접기, 전체·용어 코멘트 표시, 리뷰어 상태 표시, 요청자 본인 리뷰 차단은 모두 성공했다. 추가 데이터로 사전집 초안·리비전 diff를 확인했고, `occurrenceCount` 저장 오류를 수정한 뒤 용어 추출 접수부터 워커 콜백·초안 생성까지 성공 확인했다.
