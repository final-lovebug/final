# 전체 기능 QA 결과

검증일: 2026-09-15

## 1. 검증 범위

- 프런트: `https://ubidic.site/` 실제 배포 화면
- 브라우저: Chrome GPT 확장프로그램 연결 세션
- 계정: 기존 로그인 세션의 OWNER / ADMIN 권한 계정
- 백엔드: `./gradlew test`
- 프런트 정적 검증: `npm run build`, `npm run lint`
- 브라우저 콘솔: error / warning 로그 확인

이번 브라우저 검증에서는 기존 QA 데이터의 조회·화면 전환을 중심으로 확인했다. 운영성 데이터에 영향을 주는 회원 탈퇴, 문서·라벨 삭제, 리뷰 제출·반영은 추가로 실행하지 않고 기존 `QA_DICTIONARY_UI.md`의 성공 결과를 함께 반영했다.

## 3. 자동 검증 결과

### 백엔드

```text
./gradlew test
BUILD SUCCESSFUL
```

### 프런트

```text
npm run build
vite build successful

npm run lint
warning 1건, error 0건
```

Lint warning은 `frontend/src/pages/OAuthCallbackPage.tsx`의 effect 내부 동기 상태 변경(`react(set-state-in-effect)`)이다. 빌드를 막는 오류는 아니다.

- error: 없음

## 4. 확인된 제한 사항

- 설정 › 알림의 Slack·메일·Web Push는 현재 MVP 범위상 읽기 전용 정책 화면이다.
- 설정 › 라벨의 생성·이름 변경·삭제 API는 아직 연결되지 않았고 문서 생성/수정의 라벨로 관리된다.
- 사전집 용어 목록 응답에 정의가 없는 경우 화면에 `—`를 표시한다.
- 문서 버전 본문 diff와 사전집 리비전 diff 일부는 백엔드가 아니라 프런트에서 계산한다.
- 워커가 없는 로컬 환경에서는 추출·대조가 인프로세스 대역으로 동작하며, 실제 SQS/FastAPI 왕복은 `dev` 환경이 필요하다.
- 이번 검증은 기존 QA 데이터 보호를 위해 삭제·탈퇴·리뷰 최종 반영을 재실행하지 않았다.

## 5. 결론

핵심 사용자 흐름인 로그인 세션 → 워크스페이스 → 문서 → 사전집 공식본/초안/개정안 → 리뷰 → 설정 화면은 실제 배포 화면에서 정상적으로 열리고 주요 데이터가 표시됐다. 기존 기능 QA 기록까지 포함하면 문서 업로드, AI 추출·콜백, 후보 작성, 리비전 diff, 리뷰 집계·코멘트, 알림까지 성공 확인 범위에 포함된다.
