# 사전집 초안 단일 페이지 전환 계획

## 목표

사전집 초안 페이지 하나에서 후보어 묶음의 대표어와 정의를 정리하고, 준비가 완료되면 즉시 리뷰 요청과 사전 개정안을 생성한다.

## 화면 변경

- 상단에 사전집 초안 작성자 한 명만 표시한다.
- 후보어별 작성자·담당자·판정 상태·체크박스·일괄 처리 UI를 제거한다.
- 후보어 묶음의 대표어 선택, 직접 입력, 정의 수정, 근거 문장은 유지한다.
- 모든 후보어의 대표어와 정의가 준비되면 리뷰 요청 버튼을 활성화한다.
- 버튼 클릭 후 별도 중간 탭 없이 기존 사전 개정안 상세 화면으로 이동한다.

- 사전 개정안 화면은 후보어 묶음의 대표어만 표시한다.
    - 대표 표기인 form만 개정안 행으로 사용한다.
    - variantForms의 나머지 표현은 별도 행으로 표시하지 않는다.

## API·백엔드 로직

- ~~사전 초안 조회·목록 응답에 creatorName을 추가한다.~~ (위 「구현 상태」 참고)
- 후보어 응답에서는 createdBy를 제거한다. DB의 생성자 데이터는 감사 용도로 유지한다.
- 리뷰 요청 준비 조건은 후보어 판정 상태가 아니라 전체 후보어의 유효성으로 판단한다.
    - 모든 후보어는 대표어와 정의를 가져야 한다.
    - 기본 form 값은 대표어로 인정한다.
    - 모든 후보어의 대표어를 차기 사전집 목록에 포함한다.
    - 활성 사전집과 완전히 같으면 리뷰 요청을 거절한다.

- 기존 후보어 승인·보류·거절·편입 API와 상태 데이터는 삭제하지 않고 사용 안 함 주석으로 남긴다. 새 초안·리뷰 요청 경로에서는 참조하지 않는다.
- 리뷰 요청 API는 기존처럼 리뷰 요청과 최초 사전 개정안을 함께 생성한다.

## 프런트엔드 연동

- 워크스페이스에서 최신 EXAMINING 사전 초안 하나를 조회한다.
- 초안 정보와 후보어 목록을 함께 로드해 작성자와 후보어 묶음을 렌더링한다.
- 대표어·정의 수정 후 캐시를 갱신한다.
- 리뷰 요청 클릭 시 교정 완료 처리 후 리뷰 요청 API를 호출하고, 성공하면 생성된 리뷰 요청의 사전 개정안 상세로 이동한다.
- 후보어 작성자 이름 조회, 후보어 판정 훅, 일괄 판정 훅, 관련 UI 상태는 제거한다.

## 검증

- 초안 응답에는 creatorName이 있고 후보어 응답에는 createdBy가 없는지 검증한다.
- 정의 누락 후보어가 있으면 리뷰 요청이 거절되는지 검증한다.
- 후보어 판정 상태와 무관하게 모든 후보어 대표어가 개정안에 포함되는지 검증한다.
- 개정안 화면에서 표기 묶음의 비대표 표현이 중복 행으로 나타나지 않는지 검증한다.
- 초안 페이지에서 작성자가 한 곳에만 표시되고, 후보어별 선택·판정 UI가 없는지 확인한다.

## 가정

- 사전집 초안 페이지 URL은 유지한다.
- 리뷰어는 기존 정책대로 요청자를 제외한 워크스페이스 멤버를 기본 지정한다.
- 별도의 리뷰 요청 작성 페이지·탭은 추가하지 않는다.
