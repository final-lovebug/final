# `docs/task/` — 통합 작업 실행 체크리스트

이 폴더는 **git에 커밋되는 공유 폴더**다(`backend/task/`는 개인 비공개 추적용이라
`.gitignore`에 걸려 있지만, `docs/task/`는 걸려 있지 않다 — 혼동하지 않는다).

- **왜(결정·설계 근거)**는 `docs/plan/INTEGRATION_PLAN.md`에 있다.
- **무엇을 어떻게(실행 체크리스트)**는 여기 있다.
- **팀 공유용 진행 보고서**는 [`fe-be-1st-report.md`](fe-be-1st-report.md) — 트랙 A를
  진행하며 새로 드러난 백엔드 설계 공백·구조적 이슈를 정리했다. 팀원들과 먼저 이걸
  같이 보는 걸 추천한다.

혼자 진행할 수도, 여러 사람이 나눠 진행할 수도 있도록 **태스크 하나 = 파일 하나**로
쪼갰다. 서로 다른 태스크는 건드리는 파일이 겹치지 않는다(아래 의존 표 참고).

## 태스크를 집으려면

1. 아래 표에서 **의존이 이미 완료됐고 담당자가 없는** 태스크를 고른다.
2. 그 태스크 파일을 열어 담당자·상태를 채운다(`상태: 진행중 | 담당자: 홍길동`).
3. 체크리스트를 위에서부터 진행하며 체크한다.
4. 끝나면 `상태: 완료`로 바꾸고 PR을 올린다. 이 표의 상태 칸도 같이 갱신한다.

## 작업 원칙 (2026-09-14, 트랙 A 착수 시 확정)

- **태스크 시작 전, 그 태스크 파일의 체크리스트가 실제 코드/API와 맞는지 먼저 확인한다.**
  다르면(엔드포인트가 예상과 다르다, 응답 필드가 다르다, 대응하는 백엔드 기능 자체가
  없다 등) **코드를 고치기 전에 그 파일 체크리스트를 먼저 갱신**하고, 설계 자체가
  바뀌는 수준이면 `docs/plan/INTEGRATION_PLAN.md`도 함께 고친다.
- **여러 방안 중 하나를 임의로 골라야 하는 결정**이 나오면 코드를 고치기 전에 먼저
  사용자에게 묻는다 — 루트 `CLAUDE.md`의 "미확정 항목은 임의로 확정하지 않는다" 원칙.
  실제 사례: T-INT-13(알림 설정 API 자체가 없음 → 이번엔 건너뛰기로 결정), T-INT-11
  (개정 이력 타임라인 API 없음 → 그 항목만 건너뛰기로 결정), T-INT-10(라벨 생성 API
  없음 → 목록 조회만 실연동하기로 결정). 각 태스크 파일에 결정 이유가 기록돼 있다.
- **기존 `fixtures.ts`/`types.ts` 파일은 Write로 덮어쓰지 않고 Edit만 쓴다**
  (`frontend/CLAUDE.md` "기존 파일 수정 시 주의" — Write로 기존 내용을 날릴 뻔한 사고
  기록이 있다).
- 단순 사실 확인(정확한 엔드포인트 경로를 찾았다 등)은 묻지 않고 바로 문서를 갱신한다 —
  질문은 **선택지가 있는 결정**에만 쓴다.

**트랙 A**(프론트 목업 제거, T-INT-9~16)는 서로 완전히 독립이라 몇 명이 동시에 붙어도
된다. **트랙 B**(SQS↔FastAPI 실연동)는 T-INT-7 → T-INT-8 → T-INT-17 순서로 이어진다.
T-INT-6은 트랙 B로 분류돼 있지만 다른 태스크와 무관하게 아무 때나 처리 가능한 잡일이다.

> **`T-INT-23`(관측성)이 `X-08`의 담당을 이어받았다.** 「`ErrorResponse.traceId`는 `T-INT-3`에서」라고
> 적힌 문서들이 아직 있는데 그 태스크는 범위 밖으로 뒀었다 — 추적 기반이 `T-INT-23`에서 생기므로
> 나눌 수 없어 함께 처리한다(`docs/plan/CONFLICTS.md` `D-96`).
>
> **2026-09-14 기준 대기 태스크는 없다.** `T-INT-21`(디자인 정합)까지 코드 작성이 끝났고
> 남은 것은 수동 QA뿐이다. 트랙 B의 T-INT-7·T-INT-8은 같은 날 진행된
> **AI 워커 전환 세션**(`WLSH-166`, PR #62)이 `D-66`~`D-78`로 설계를 다시 잡으면서 다른
> 모양으로 이미 끝나 있었고(각 파일에 대조표를 남겼다), 마지막 남은 T-INT-17을 그 위에서
> 마쳤다. 남은 것은 **수동 QA**와 **저장소 밖의 FastAPI 워커 구현**뿐이다.
>
> **ID 충돌 주의** — 이 표의 `T-INT-6`(NotificationController)과
> `docs/plan/EXECUTION_ORDER.md`의 `T-INT-6`(AI 워커 전환)은 **서로 다른 태스크다.**
